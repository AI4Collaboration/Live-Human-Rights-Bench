# Data Directory Structure

This directory contains all data for the LLM Human Rights Research project.

**The descriptions below document the historical 141-pair pilot.** The current
1,000-instance, year-balanced evaluation pool is specified in the repository
[README](../README.md#current-evaluation-dataset-year-balanced-deepseek-summaries)
and [dataset contract](../DATA_SPLITS.md). Do not use historical summary versions
or result files as substitutes for the current input release.

## Directory Overview

```
data/
├── processed/              # Main cleaned dataset ready for use
├── summaries/             # All 12 summary versions (4 models × 3 versions each)
└── experiments/           # All experiment results organized by research question
    ├── rq1_summarization/
    ├── rq2_framing/
    └── rq3_confidence/
```

## Detailed Structure

### 1. `processed/` - Main Dataset

**File**: `echr_cases_final_clean.json`
- **Description**: 141 ECHR case-article pairs with verdicts surgically removed
- **Format**: JSON array of case objects
- **Fields**:
  - `case_name`: Name of the ECHR case
  - `article`: ECHR Article number
  - `violation_label`: Ground truth ("violation" or "no_violation")
  - `case_text`: Full case text with verdict removed
  - `step1_summary`: Initial extractive summary
  - `facts`: Extracted facts
  - `procedure`: Legal procedure information
  - `relevant_law`: Applicable legal framework

### 2. `summaries/` - Summary Versions

Contains 12 summary versions generated by different models:

**GPT-4o summaries:**
- `gpt4o_v1.json`
- `gpt4o_v2.json`
- `gpt4o_v3.json`

**GPT-5.2 summaries:**
- `gpt5_2_v1.json`
- `gpt5_2_v2.json`
- `gpt5_2_v3.json` ⭐ (Best performing summary)

**Claude Sonnet 4.5 summaries:**
- `claude_sonnet_4_5_v1.json`
- `claude_sonnet_4_5_v2.json`
- `claude_sonnet_4_5_v3.json`

**DeepSeek v3.2 summaries:**
- `deepseek_v3_2_v1.json`
- `deepseek_v3_2_v2.json`
- `deepseek_v3_2_v3.json`

Each summary file has the same structure as `processed/echr_cases_final_clean.json` but with an additional `summary` field containing the generated summary.

### 3. `experiments/` - Research Question Results

#### `rq1_summarization/` - Summarization Effect

Tests whether case summaries affect LLM judgment accuracy.

**Structure:**
```
rq1_summarization/
├── evaluations/
│   ├── original_text/          # Baseline evaluations on full text
│   │   ├── gpt-4o_original_text.csv
│   │   ├── gpt-5.2_original_text.csv
│   │   ├── claude-sonnet-4.5_original_text.csv
│   │   └── deepseek-v3.2_original_text.csv
│   ├── detailed/                # Evaluations on each summary (48 files)
│   │   └── {evaluator}_summary_{summary_version}.csv
│   ├── accuracy_matrix.csv      # Accuracy for all combinations
│   ├── alignment_matrix.csv     # Self-consistency metrics
│   └── results.csv              # Summary statistics
├── analysis/
│   └── (empty - analysis results in statistical_tests/)
└── statistical_tests/
    └── rq1_comprehensive_tests.csv  # McNemar's test + Bootstrap CIs for all 48 comparisons
```

**Key Finding**: 7/48 comparisons show significant improvements (p < 0.05), all involving GPT-4o summaries.

#### `rq2_framing/` - Framing Effect

Tests how prompt framing ("will rule" vs "should rule" vs "occurred") affects judgments.

**Structure:**
```
rq2_framing/
├── evaluations/
│   └── detailed_results.csv     # All evaluations (3 framings × 4 evaluators × 141 cases)
├── analysis/
│   └── rq2_directional_analysis.csv  # Direction of changes (toward/away from violation)
└── statistical_tests/
    └── (statistical tests to be added)
```

**Key Finding**: All models show systematic bias away from finding violations (67-94% of changes).

#### `rq3_confidence/` - Confidence Challenge

Tests how models respond when challenged with "Are you sure?".

**Structure:**
```
rq3_confidence/
├── evaluations/
│   ├── gpt-4o_confidence_challenge.csv
│   ├── gpt-5.2_confidence_challenge.csv
│   ├── claude-sonnet-4.5_confidence_challenge.csv
│   └── deepseek-v3.2_confidence_challenge.csv
├── analysis/
│   ├── rq3_directional_analysis.csv     # Overall change statistics
│   ├── rq3_transition_details.csv       # Detailed transition analysis
│   └── rq3_accuracy_effects.csv         # Impact on accuracy
└── statistical_tests/
    └── (empty - confidence challenge is exploratory)
```

**Key Finding**: Challenges cause polarization (39-80% of changes) and flipping (39-80%), rarely moderation (0-20%). All models show systematic conservative bias.

## File Formats

### CSV Files (Evaluations)

**Columns:**
- `case_name`: ECHR case name
- `article`: Article number
- `violation_label`: Ground truth label
- `avg_rating`: Average rating across 10 samples (1-5 scale)
- `is_accurate`: Whether prediction matches ground truth
- `num_abstentions`: Count of rating=3 (abstention)
- `num_samples`: Total samples (always 10)
- `sample_ratings`: List of individual ratings

**Rating Scale:**
- 1 = Strong no violation
- 2 = Slight no violation
- 3 = Abstention/uncertain
- 4 = Slight violation
- 5 = Strong violation

**Binary Prediction:** `avg_rating > 2.5` → "violation", else "no_violation"

### JSON Files (Case Data)

**Structure:**
```json
[
  {
    "case_name": "CASE OF ...",
    "article": "8",
    "violation_label": "violation",
    "case_text": "...",
    "step1_summary": "...",
    "summary": "...",  // Present in summary files
    "facts": "...",
    "procedure": "...",
    "relevant_law": "..."
  }
]
```

## Data Size Summary

- **Processed dataset**: 14 MB
- **All summaries**: 180 MB (12 files × ~15 MB each)
- **All experiments**: 1 MB
- **Total**: ~195 MB

## Usage Notes

1. **Main dataset**: Use `processed/echr_cases_final_clean.json` for all experiments
2. **Best summary**: `summaries/gpt5_2_v3.json` performed best (76.1% accuracy, 82.7% alignment)
3. **Evaluator models tested**: GPT-4o, GPT-5.2, Claude Sonnet 4.5, DeepSeek v3.2
4. **Sample size**: 141 case-article pairs (100 unique cases, some with multiple articles)
5. **Samples per evaluation**: 10 independent samples with temperature=1.0

## `audits/verdict_spans/` - Quoted evidence of verdict leakage

Output of `scripts/audit_verdict_spans.py` over the 1,000-instance pool. Each row is a
case-article instance with the sentences that give its outcome away, quoted verbatim and
carrying the character offsets at which they sit in `full_case_text_no_verdict`, so any
positive can be checked against the source rather than taken on trust. A quote the model
could not have found in the text is dropped and counted, never scored.

| file | corpus | leak | review | clean |
|---|---|---|---|---|
| `dsv41flash_postcuts.json` | current inputs, `8c43527`, detector pass 1 | **0** | 10 | 990 |
| `dsv41flash_postcuts_pass2.json` | current inputs, detector pass 2 | **0** | 12 | 988 |
| `postcut_verification_20260916.json` | current inputs, relocation and direct review | **0** | 12 | 988 |
| `dsv41flash_postrepair.json` | released inputs, `d54b3bc` | **10** | 13 | 977 |
| `dsv41flash.json` | pre-repair, `ecb5e60` | 549 | 72 | 379 |
| `dsv41flash_run1_no_admissibility_class.json` | pre-repair, earlier prompt | 494 | 0 | 506 |

**For the current corpus read the three top rows together.** Two independent detector
passes over the inputs as they stand after `8c43527` put nothing in the leak tier, and
`postcut_verification_20260916.json` reaches the same place by relocating every verified
quote after the cuts and reviewing what remained, which is a check rather than a third
pass. No row states this Court's conclusion, none recites what an earlier instance
decided, and the Registry keyword line that 251 instances carried before the repair is
absent from all 1,000.

There are two detector passes rather than one because a single pass does not bound what a
detector misses, and the review tier shows why: the same corpus yields 10 rows in one pass
and 12 in the other, agreeing on 6. At temperature 0 the provider still routes differently,
and whether the model bothers to quote a boilerplate admissibility sentence moves with it.
Read the union rather than either file alone, and say that two passes found nothing rather
than that nothing is there.

- `adjudication_20260915.json` - every one of the 23 flagged rows read in context, with a
  verdict and a reason. The leak tier holds 10 of 10; two review rows were upgraded. Note
  the status field: one reader, who also wrote the detector, is not an independent
  annotator pass, so this is not yet a rate for the paper.
- `procedural_history_cuts.json` - the applied repair produced by
  `scripts/cut_procedural_history.py`: eleven judgments, twelve instances and 2,456
  characters, with every non-text field and untouched row unchanged.
- `postcut_source_reviews.jsonl` - direct source approvals for the eleven changed
  model-visible inputs after the cut and 50,000-character boundary review.

What survived the first repair was one thing no structural rule reaches: a Grand Chamber
judgment reciting what the Chamber decided on the same complaint, in PROCEDURE, above the
facts. Those outcome sentences have now been removed from the current release.

Deciding whether any of this changed a model's answer still needs the ablation: blank the
spans, rescore, and see whether the gap moves. The append-only `.jsonl` checkpoints beside
each report are working files and are not tracked.
